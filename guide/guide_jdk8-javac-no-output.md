## 问题背景

刚到公司报道第一天, 配置环境时竟然在jdk配置上出了问题: 在终端输入 `java -version` 正常显示，但输入 `javac -version` 却没有任何输出或报错”, 简单分析: java是 JRE 的指令, 而javac是JDK的指令, 也就是说安装jdk时可能只安装了 JRE 而不是完整 JDK, 但是确认公司给的安装包确实是 JDK, 排查后发现是安装程序执行过程中的一个异常设置点

如果你也遇到 `javac` 无法识别或报错的问题, 可以一起看看. 下面详细分析下原因以及解决方法

---
## 原因分析
根本原因: 环境变量中指向的路径为 JRE (预期是 JDK)

导致原因:

在安装 **Oracle JDK 8** 的官方安装包时，安装程序为了照顾当时的普通用户，设计了死板的**两步走**逻辑：
1. **第一步（安装 JDK）：** 提示你安装真正的开发工具包（默认路径为 `C:\Program Files\Java\jdk1.8.0_xxx`）。
2. **第二步（安装独立 JRE）：** 在 JDK 刚刚安装完后，会**紧接着强制弹出一个一模一样的新窗口**，提示选择“目标文件夹”以单独安装一个运行环境（默认路径为 `C:\Program Files\Java\jre1.8.0_xxx`）。如图:
   ![测试](https://raw.githubusercontent.com/fengdongnan/image-bed/main/img/jre.png)

如果安装时以为是傻瓜式安装, 但又有自己修改存储路径的习惯(比如我这次第一个弹窗路径没有修改, 以为是第二个弹窗并对其进行修改), 就会导致:

* **病因 A（文件覆盖）：** 在第二步弹窗时，误以为是重新确认刚才的路径，于是点击“更改”，**把 JRE 的安装路径强行选成了刚才 JDK 的路径**。结果导致 JRE 的文件直接覆盖了 JDK 的文件，把 `bin` 目录里的 `javac.exe`（编译器）给顶掉了。
* **病因 B（路径配错）：** 将两步安装在了不同的文件夹（一个 `jdk...`，一个 `jre...`），但在最后配置系统环境变量时，因为对最后弹出的 `jre` 文件夹印象最深，**误将 `JAVA_HOME` 指向了纯运行环境的 `jre` 目录**。

由于 JRE 内部只包含让程序运行的虚拟机，**根本没有打包 `javac` 编译器**，因此后续在终端配置和执行编译命令时必然宣告失败。

---

## 解决方案
既然已经知道为什么出错: 即在环境变量中配置的路径是 JRE 的路径,修复操作本质就是让环境变量path重新正确指向jdk路径, 可以尝试以下方法：


### 1.推荐斩草除根,直接删除重来

 如果和我一样是病因 B, 那么本地已经有了混乱的JDK, JRE. 为了彻底清理防范后续问题:

1.环境变量中配置的路径 path a 不要变动, 删除 path a 下的 JRE 和默认安装路径下的 JDK

2.重新执行安装程序, 但是注!! 在第一次弹出路径修改(JDK路径) 时将路径修改为 path a

3.第二次弹出路径修改(JRE), 跳过

4.完成, 这样不用修改之前配置过的环境变量, 现状就是 path a 指向 JDK, 预期 javac 可以正常执行

### 2.找到真实JDK路径重新配置环境变量
适合不想再重新安装, 且对JDK位置没有强迫症的人:

1.检查 JDK 完整性

打开 jdk 安装目录（`C:\Program Files\Java\jdk1.8.0_xxx`）：
- 观察根目录下是否同时存在 **`bin`** 和 **`include`** 文件夹（JRE 没有 `include` ）
- 点进 **`bin`** 文件夹，检查是否包含 **`java.exe`** 和 **`javac.exe`** 

> *如果找不到 `javac.exe`，说明文件已被覆盖损坏，直接删除重装。*

确认了真正包含 `javac` 的 JDK 根目录，开始精确配置：

2.修改 JAVA_HOME： 将系统变量 JAVA_HOME 的值更新为真实的 JDK 根目录路径（末尾无需加 \ 或 \bin） 

3.置顶 Path 变量： 编辑系统 Path 变量，确保包含 %JAVA_HOME%\bin，并将其上移至首行（防止被其他 JRE 路径覆盖）。

4.验证: 保存设置后，重新打开一个新的终端(**必须关闭旧的命令行，重新打开一个新的 `cmd` 窗口**)输入 javac -version 确认是否生效

---

## 三、 注意事项

1. **第二步的弹窗完全可以“直接关闭”** :其实 JDK 内部已经默认自带了一个完整的 JRE（就在 `jdk/jre` 目录里），官方在第二步额外赠送的独立 JRE **对于程序员开发来说是完全多余的**。下次再遇到第二步弹窗，**直接点击右上角的 `X` 关掉拒绝安装**
2. **建议全面转向“绿色版”或“OpenJDK”** : Java 11 / 17 / 21 及现代 OpenJDK 8 的安装包早就废除了这种两步走的恶心设计。更推荐直接去诸如 **Adoptium (Temurin)** 官网下载纯正的 `.zip` 绿色压缩包，解压即用，从根源上杜绝安装包的弹窗暗坑。
